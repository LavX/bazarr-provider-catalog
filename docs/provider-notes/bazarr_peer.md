# Bazarr+ Peer Provider Notes

## Upstream

- Search: `GET /api/v1/subtitles` on each peer, with the `Api-Key` header only. Search sends no bearer token.
- Search parameters: `languages` (one comma-separated value that holds every requested code; `pt-BR` for Brazilian Portuguese, the base code otherwise; hearing-impaired requests are searched as the plain language), `type` (`movie` or `episode`), `imdb_id` (`tt` plus seven digits; the series id for episodes), `tmdb_id` when no IMDb id is known, `season_number` and `episode_number` (episodes), `query` (the file name, for tmdb-only episodes), `moviehash` and `moviebytesize` (under `use_hash`), `exclude_providers=bazarr_peer`, `only_providers=local` (under `library_only`), `timeout_seconds` (the time left in the search budget, rounded up to whole seconds, at least 1 and at most 90), and `page=1`. No `per_page` is sent.
- Response: `data`, `total_count`, `total_pages`, `per_page`, and `page`. Each row carries `attributes.subtitle_id`, `attributes.files[0]` (`file_id`, `file_name`), `attributes.language`, `attributes.release`, `attributes.moviehash_match`, `attributes.hearing_impaired`, `attributes.foreign_parts_only`, `attributes.ai_translated`, `attributes.url`, `attributes.download_count`, `attributes.feature_details`, and `attributes.uploader.name`.
- Providers probe: `GET /api/v1/providers` with the `Api-Key` header only lists the provider names the peer serves. It is not metered. The provider uses it for library checks and to classify a 404 from the search route.
- Login and download: `POST /api/v1/login` with the `Api-Key` header only returns a token. `POST /api/v1/download` with the `Api-Key` header, the bearer token, and the body `{"file_id", "sub_format": "srt"}` returns a stream `link`. The link is then fetched with no auth headers.
- Revision: the parameters and fields above follow the Bazarr+ compat API in Bazarr development commit f30e69b8e. Check this section when that API changes.

## Endpoints And Keys

- `endpoints` is a whitespace-separated list of base URLs. `api_keys` holds one key per endpoint, in the same order. The two counts must match. Each key is printable ASCII without spaces.
- Each URL must use `http` or `https` and carry a host. Credentials, query strings, and fragments are refused. A trailing slash is removed and the base path is kept. The host and path must be ASCII.
- Every entry is validated, including entries past the sixteenth. Duplicate normalized URLs are refused. The first 16 endpoints are used, and the rest are logged and dropped in one line.
- An endpoint's tag is the first 16 hex characters of the SHA-256 of its normalized URL. Candidate ids have the form `<tag>:<subtitle id>`, and download payloads carry the tag.
- The OpenSubtitles service (`api.opensubtitles.com` and its subdomains) is refused at configuration time, before any request. The key is never sent there.
- `timeout_seconds` is the whole-search budget, from 30 to 90 seconds, with 45 as the default. Every endpoint searches in parallel inside that budget.
- `library_only` (default on) limits the search to the peer's own library. `use_hash` (default on) sends the file hash. `include_ai_translated` (default off) keeps subtitles the peer marks as AI translated. The peer reports that flag as false for local rows; see Known Gaps.

## Search And Download

- Each endpoint gets one search request per search, for page 1. The request carries every requested language in one comma-separated value. Forced requests are not searched, because the peer has no forced-only search.
- The request's timeout is the time left in the search budget. An endpoint that the budget ends before its request is skipped and logged as `budget_spent`. No request is sent and no cooldown is set.
- When `total_count` is larger than the rows received, the search logs `more_results_not_fetched` and raises nothing. Later pages are never requested.
- A failed endpoint contributes no results, and its failure logs one line with the endpoint tag, the exception class, and a reason. The candidates of the other endpoints are kept. A valid empty response is a success.
- A search raises for invalid settings, and when every endpoint failed. If they failed the same way, it raises that class: `APIThrottled` with the longest Retry-After, `AuthenticationError`, or `ConfigurationError`. Otherwise it raises `ServiceUnavailable`. A rate limit on one endpoint never raises while another endpoint returns candidates.
- Search status handling: 400 is a `ConfigurationError` (reason `bad_request`). 401 and 403 are `AuthenticationError`, and a search never logs in again. 429 is `APIThrottled`. A 503 whose JSON error is the compat-disabled message is a `ConfigurationError` that reads "Distribution Hub is off on this instance". Any other 503 is a transient failure with reason `peer_unavailable`. Other 5xx responses, redirects, and timeouts are endpoint failures.
- A 404 from the search route with the `x-reason: compat-disabled` header is "Distribution Hub is off", and no probe runs. Any other 404 runs the providers probe. A 200 probe means the subtitles route is missing (reason `version_or_path`). A 404 probe means the address is not a Bazarr+ instance (reason `not_bazarr_plus`). A compat-disabled 404 or 503 probe is "Distribution Hub is off". A 401 or 403 probe is an authentication failure. Any other probe answer is a transient failure with reason `peer_unavailable`.
- A 429 cools its endpoint for the Retry-After interval, capped at one day. Without a usable Retry-After, which covers a missing header, zero, a negative or non-integer value, and an HTTP date, the cooldown is 60 seconds. The cooldown holds even when another endpoint succeeds in the same search.
- Any other failed search in which the endpoint sent its request also cools it for 60 seconds. The recovery search in a download is governed by the recovery rules below, not by this sentence. Cooldowns are kept per endpoint and per key, so a corrected key is queried in the next search. A cooled endpoint replays the error that cooled it.
- Library-only searches: when a library-only search returns no rows from an endpoint, the provider checks the providers probe. The check runs only when the rows are empty before the AI-translated filter, so a search emptied only by that filter does not probe. If the peer lists no `local` provider for this key, the endpoint is logged as `library_not_served` and contributes nothing. The probe answer is kept for 10 minutes per endpoint and key, in worker memory only.
- The probe is not sent when the search budget is spent, and it waits at most the time left in that budget. A 401 or 403 probe is an `AuthenticationError`, and a compat-disabled probe is "Distribution Hub is off". Any other probe failure (a timeout, a 404 without the compat-disabled header, a 503, or another status) is logged as `probe_failed` with its exception class. The empty result stands. A refused probe sets no cooldown, because the search itself answered.
- Hash: the file hash comes from the payload when it carries one, checked in the order `bsplayer`, `opensubtitlescom`, `napisy24`, then `opensubtitles`. Otherwise it is computed from the local file: its size plus the first and last 64 KiB, read as little-endian 64-bit words. A file under 128 KiB, or an unreadable path, sends no hash, and the search goes on without it. The log names the exception class, never the path.
- A candidate claims its hash only when the peer reports `moviehash_match` and the row names a release. The peer's `url` becomes `page_link` only when it is not empty. The candidate carries the peer's `ai_translated` flag at the top level, so the host can honor it. The peer reports `false` there for local rows; see Known Gaps.
- Candidates from one endpoint are deduplicated on the candidate id, and the first row wins.
- Local rows (subtitles the peer stores) get a new trailing file id on every search. Their stable key is the subtitle id without that trailing id, plus the file name.
- The download payload keeps the endpoint tag, the row kind, the subtitle id, the file extension, the file id, and the search context with its stable key. A query longer than 128 characters is dropped from the context and logged as `query_dropped`. A payload over 1024 bytes drops its context and stable key, keeps the other fields, and is logged as `context_too_large`. A later 404 for such a payload skips as `stale_no_context`.
- A 404 from the download request runs one recovery search with the saved context, and downloads the row whose stable key matches, using its fresh file id. Without a match the download is skipped as `stale_not_found`. A second 404 after the recovery skips as `not_found`. A download call runs at most one recovery.
- Download status handling: 406 with the throttled reason is a skip (quota). 404 starts the recovery above. 400 is a `ConfigurationError`. 401 re-mints the token once, then raises `AuthenticationError`. 403 raises `AuthenticationError` without a re-login. 429 raises `APIThrottled` and cools the endpoint. A compat-disabled 404 or 503 raises "Distribution Hub is off". Transient failures of the download request, such as a timeout, an unreachable endpoint, a 5xx, or a redirect, skip the candidate. A TLS handshake failure raises `ConfigurationError`, as it does in search.
- The login call follows the same status rules. A redirect or a transient failure on the login skips the candidate.
- The recovery search reports its failures as candidate skips: a 429 cools the endpoint and skips as `recovery_throttled`; a 401 or 403 skips as `recovery_rejected`, with no cooldown and no second login; a 400 skips as `bad_request`; a compat-disabled answer skips as `compat_disabled`; any other failure skips as `recovery_failed`. A TLS handshake failure on the recovery search raises `ConfigurationError`, as it does in search. A 5xx, a timeout, or a redirect on the recovery search skips as `recovery_failed` with no cooldown. A recovery whose budget is already spent sends nothing and skips as `budget_spent`.
- The stream link must have the endpoint's scheme, host, and port, and a path under the endpoint's base path followed by `/api/v1/download/stream/`. Otherwise the candidate is skipped as `link_origin_mismatch`. A mismatch usually means a reverse proxy that does not forward `X-Forwarded-Proto` or `X-Forwarded-Host`. The check is not relaxed.
- The stream fetch has its own 30-second deadline. It sends no auth headers and refuses redirects. A 200 with an empty body is skipped as `content_missing`. A 410 is `stream_expired`, a 403 is `blocked_by_peer` (the peer's SSRF guard), a 404 is `not_found`, and a 503 is `peer_unavailable`. Any other status, including a redirect, skips the candidate with the status in the reason. A TLS handshake failure on the stream raises `ConfigurationError`, as it does on login, download, and search.
- The content is checked in this order. An empty body is skipped. A RAR archive is skipped. A ZIP archive is returned for the host to extract. A JSON body and a web page are skipped. Anything else is returned as subtitle text. The download declares no encoding; the host detects it when it normalizes the text.
- Logs carry the endpoint tag, the exception class, and a reason. They never carry keys, tokens, links, URLs, or response bodies.

## Known Gaps

- `library_only` needs the peer to serve its library to this key. A peer with serve-local turned off, or a key whose allow-list leaves out `local`, returns no candidates from that endpoint, logged as `library_not_served`. Changing that setting on the peer is outside this provider.
- A context over 1024 bytes is dropped and logged as `context_too_large`, and that subtitle cannot be recovered after a peer restart. A query over 128 characters is not kept in the context.
- The search budget is at most 90 seconds, the limit this provider sends to the peer. A configured value outside 30 to 90 is refused.
- The download call has a 30-second budget. Its login, its download request, and its one recovery search share that budget. The stream fetch has a 30-second deadline of its own.
- The library probe answer is cached for 600 seconds, in worker memory only.
- A link origin mismatch is refused, not relaxed. Operators behind a reverse proxy must forward `X-Forwarded-Proto` and `X-Forwarded-Host`, so that the peer builds links at the configured address.
- The manifest lists plain language codes and declares no hearing-impaired variants.
- The peer reports `ai_translated` as false for local rows (subtitles the peer stores). `include_ai_translated` therefore cannot tell an AI translated library subtitle from a human one. The provider passes the peer's flag through and does not verify it or infer provenance.
- The 60-second cooldown default is provisional. A two-instance check, with one instance querying another, would settle it.
